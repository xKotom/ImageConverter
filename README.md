# ImageConverter — конвертер изображений

Курсовая работа: настольное Windows-приложение для пакетной конвертации фотографий
(C++20, Qt 6 Widgets, CMake). Проектирование и план — по документу
«Универсальный конвертер изображений — архитектура и план реализации».

Приложение определяет формат по содержимому, показывает предпросмотр и предупреждения о потерях, конвертирует
пакетом в фоне и не теряет исходные данные при сбое. Интеграция с Проводником Windows запланирована
на следующие этапы (см. «Что осталось»).

### Что сделано, по порядку

1. **Ядро и фото-MVP (этапы 0–4).** Слои `domain → application → infrastructure → ui`; импорт файлов и папок;
   `FormatDetector` (сигнатуры), `FileAnalyzer`, `ConversionPlanner` (предупреждения до запуска), `ConversionEngine`,
   `QueueManager` с пулами потоков, `AtomicFileWriter` (временный файл → проверка → переименование), `OutputNamer`,
   предпросмотр с debounce и кэшем, `SettingsManager`, разбор командной строки.
2. **Этап 5.** Кодеки libheif (HEIC/AVIF), giflib (запись GIF), libwebp (анимированный WEBP), libtiff (многостраничный TIFF);
   перенос метаданных EXIF/XMP/IPTC через exiv2 с отдельной политикой для GPS; сохранение всех кадров анимации;
   `CapabilityReport` — реальная поддержка форматов в окне и в консоли.
3. **Редизайн.** Интерфейс в духе macOS/iOS: карточки, сегментированные переключатели, переключатель как в iOS,
   лента файлов со значками форматов; настройки вынесены в окно «Дополнительно…»; светлая/тёмная/системная тема;
   **стеклянный стиль** с настоящим размытием фона (акрил Windows); название **ImageConverter** и значок.
4. **Исправления по результатам проверки.** Минимальная высота окна подогнана под экраны 720p/масштаб 200%
   (правая панель прокручивается); выпадающий список формата красится под тему и раскрывается под полем;
   фон окна в обычном режиме закрашивается явно; значок окна подключён через ресурсы Qt.

### Что осталось

**Этапы плана**

- **Этап 7 — стабилизация:** установщик, проверка на чистой Windows 10/11, итоговая проверка лицензий и версий
  зависимостей, ручное тестирование интерфейса на разных масштабах экрана и в обеих темах.
- **Этапы 8–10 — интеграция с Проводником:** отдельная нативная COM-библиотека (`platform/windows`), команда
  «Конвертировать» с подменю форматов (вариант Б), миниатюры и Preview Handler для фото и видео.

**Доработки фото-части (известные ограничения)**

- Запись HEIC (нужен HEVC-кодировщик, лицензия GPL — сейчас отключено), анимированный HEIC/AVIF.
- Перенос метаданных в BMP, GIF, AVIF и HEIC; определение ICC-профиля при быстром зондировании для всех форматов.
- Отмена посреди декодирования одного файла (сейчас — между этапами конвертации).
- Дизеринг для GIF, APNG, RAW, история конвертаций (SQLite — по ТЗ при появлении требований).

**Для сдачи курсовой**

- Пояснительная записка и диаграммы (архитектура, классы, последовательности) на основе ТЗ и этого описания.

## Возможности

- Добавление файлов, папок (рекурсивно) и drag & drop; повторы отбрасываются; импорт идёт в фоне.
- Формат определяется **по содержимому** (сигнатуры + проверка декодером); расширение — только подсказка.
  `photo.jpg`, внутри которого PNG, распознаётся как PNG с предупреждением.
- Доступные форматы строит `CodecRegistry` из реально загруженных кодеков: нет кодировщика — формат не предлагается.
- Предупреждения **до** запуска: потеря прозрачности (заливка выбранным фоном), сжатие с потерями,
  потеря ICC/метаданных, анимация (все кадры / первый кадр / отказ), несовпадение расширения, GPS.
- Очередь: ожидание → выполнение → успех / ошибка / отмена / пропуск, прогресс по каждому файлу,
  отмена, явный повтор, ограниченная параллельность (по умолчанию 2 потока). Ошибка одного файла не останавливает пакет.
- Безопасная запись: временный файл с непредсказуемым именем в папке назначения → проверка
  (размер, повторное чтение, размеры, число кадров) → переименование. При ошибке/отмене остаток удаляется. Исходник не
  изменяется и никогда не выбирается как путь результата. Конфликт имён: суффикс `(1)`, замена (с подтверждением) или пропуск.
- Предпросмотр: debounce выбора, отмена устаревшего запроса, scaled read, LRU-кэш с ключом из пути/времени/размера/версии декодера.
- Командная строка: `ImageConverter.exe [файлы...] --format webp --quality 85 --output D:\out --start`,
  `--list-codecs` — вывести доступные форматы.
- Настройки хранятся в `%APPDATA%\ImageConverter\settings.ini`.

## Интерфейс

Дизайн в духе macOS/iOS: карточки со скруглёнными углами, сегментированные переключатели, переключатель как в iOS,
лента файлов со значками форматов и статусами-«таблетками», значки нарисованы векторно (без внешних файлов).

**Главный экран.** Слева — крупный предпросмотр с информацией о файле и предупреждениями, под ним очередь.
Справа — формат и качество, зона перетаскивания, кнопки «Дополнительно…», «Конвертировать», «Отмена», «Повторить»
и ссылка «Поддерживаемые форматы». Правая панель прокручивается, поэтому окно можно делать невысоким.

**«Дополнительно…»** — окно настроек со сгруппированными строками:

| Раздел | Настройки |
|---|---|
| Сохранение | рядом с исходным файлом (переключатель), папка сохранения, «Если файл уже есть» (суффикс / заменять / пропускать) |
| Содержимое | анимация и страницы, метаданные (удалить / без GPS / всё), фон вместо прозрачности |
| Оформление | тема (системная / светлая / тёмная), стеклянный стиль |

Краткая сводка настроек показана под кнопкой «Дополнительно…».

**Тема и стекло.** Тема следует за Windows или задаётся вручную. **Стеклянный стиль** — окно полупрозрачное, сквозь него
видны рабочий стол и окна позади, размытые системой (акрил Windows 10 1803+ / Windows 11, включая заголовок окна);
панели матовые. Если размытие недоступно, используется цветной градиентный фон. Изменения видны сразу,
«Отмена» возвращает прежний вид, «Готово» запоминает выбор. Для проверки внешнего вида схему можно принудительно
задать переменной окружения `UIC_THEME=light|dark`.

## Форматы (этап 5)

Окно «Поддерживаемые форматы» и `ImageConverter.exe --list-codecs` показывают то, что **реально подтверждено при запуске**.

| Формат | Чтение | Запись | Анимация / страницы | Метаданные (запись) | Библиотека |
|---|---|---|---|---|---|
| JPEG, PNG | да | да | — | да | Qt Image I/O |
| BMP | да | да | — | нет | Qt Image I/O |
| WEBP | да | да | чтение и запись всех кадров | да | Qt + libwebp (анимация) |
| GIF | да | да | чтение и запись всех кадров | нет | Qt (чтение) + giflib (запись) |
| TIFF | да | да | многостраничные: чтение и запись | да | Qt + libtiff (страницы) |
| HEIC/HEIF | да (HEVC) | **нет** (лицензия x265/GPL) | — | нет | libheif + libde265 |
| AVIF | да | да | — | нет | libheif + aom/dav1d |

- **Анимация** (политика): «все кадры» (по умолчанию, если формат результата это умеет), «только первый кадр» либо «отклонять».
  Задержки между кадрами и число повторов сохраняются; проверка результата сверяет число кадров.
  GIF: общая палитра ≤256 цветов (медианное сечение, без дизеринга), прозрачность однобитная.
- **Метаданные EXIF/XMP/IPTC** (exiv2): GPS переносится только по явному выбору. Ориентация в результате сбрасывается
  в 1 (она уже применена к пикселям), структурные теги исходного контейнера и встроенная миниатюра не копируются.
  Сбой переноса не уничтожает результат — он попадает в предупреждения.
- **HEIC/AVIF**: из файла берётся основное изображение; трансформации контейнера (поворот/зеркало) применяет libheif.
  Запись HEIC включается сборкой `-DUIC_ENABLE_HEIC_ENCODE=ON` (лицензия итоговой программы должна быть совместима с GPL).

## Архитектура

```
app/                  точка входа и корень композиции (выбор реализаций портов)
resources/            значок приложения (icons/, app.qrc, app.rc)
scripts/              deploy.sh — автономная папка с DLL
src/domain/           форматы, модели, состояния, Result — без Qt и Windows API
src/application/      сценарии: импорт, анализ, план, движок, очередь, превью;
                      порты IImageDecoder / IImageEncoder / IMetadataService
src/infrastructure/   qt_imageio (QImageReader/Writer), codecs (libheif, giflib, libwebp, libtiff),
                      metadata (exiv2), settings (QSettings)
src/ui/               Qt Widgets: MainWindow, FileListModel, DropArea, AdvancedSettingsDialog,
                      CapabilitiesDialog, Theme (темы и стекло), ToggleSwitch, SegmentedControl, ColorWell, Icons
tests/                unit и integration (Qt Test)
```

Зависимости направлены к абстракциям: `ui → application → domain ← infrastructure`.
`uic_core` (domain + application + infrastructure) не зависит от Qt Widgets; GUI-поток не декодирует и не конвертирует.

| Класс | Роль |
|---|---|
| `FileImporter`, `FileValidator`, `FileAnalyzer`, `FormatDetector` | импорт, проверка пути, анализ, сигнатуры |
| `CodecRegistry` | реестр возможностей чтения/записи, анимации и метаданных |
| `ConversionPlanner` | совместимость и предупреждения до запуска (анимация, метаданные, потери) |
| `CapabilityReport` | описание реально доступных возможностей для окна и консоли |
| `ConversionEngine` | decode → ImageBuffer → encode → метаданные → проверка → фиксация |
| `QueueManager` | задачи, состояния, пулы потоков, отмена, повтор |
| `OutputNamer`, `AtomicFileWriter` | имена и атомарная запись |
| `PreviewController`, `ThumbnailGenerator`, `PreviewCache` | предпросмотр |
| `SettingsManager`, `CommandLineHandler` | настройки и аргументы запуска |
| `Theme` | палитры, стили QSS, светлая/тёмная схема, стеклянный фон и размытие окна |

## Тесты

Три набора на Qt Test (`ctest`): `test_unit` (логика без кодеков: сигнатуры, имена, атомарная запись, планировщик,
кэш), `test_integration` (реальные кодеки, очередь, предпросмотр, сквозные сценарии) и `test_stage5`
(HEIC/AVIF, GIF/WEBP/TIFF, анимация, метаданные, юникодные пути). Интерфейс проверялся вручную по скриншотам.

## Сборка и запуск (Windows, MSYS2 UCRT64)

```bash
pacman -S mingw-w64-ucrt-x86_64-{gcc,cmake,ninja,qt6-base,qt6-imageformats,qt6-tools,libheif,exiv2,libtiff,giflib,libwebp,aom,libde265,dav1d}
export PATH=/c/msys64/ucrt64/bin:$PATH
cmake -S . -B C:/uic-build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build C:/uic-build
ctest --test-dir C:/uic-build --output-on-failure
```

Важно: **каталог сборки должен быть с ASCII-путём** (например `C:\uic-build`): `moc` и `windres` не работают
с путями с кириллицей, как у папки «Курсовая работа».

Для запуска без MSYS2 соберите автономную папку: в оболочке MSYS2 UCRT64 выполните `scripts/deploy.sh /c/uic-build`
(windeployqt + все остальные DLL). После этого `ImageConverter.exe` запускается двойным щелчком.
Значок и сведения о программе встраиваются в exe автоматически (`resources/app.rc`), значок окна — через `resources/app.qrc`.
Перед пересборкой закройте запущенный `ImageConverter.exe`.

## Известные ограничения

- Метаданные не пишутся в BMP, GIF, HEIC и AVIF (приложение предупреждает до запуска).
- ICC сохраняется там, где формат его поддерживает; у исходников при быстром зондировании наличие ICC определяется не для всех форматов.
- Отмена срабатывает между этапами конвертации, а не посреди декодирования одного файла.
- Все кадры анимации держатся в памяти (лимит ≈1,5 ГиБ); для очень длинных анимаций выберите «только первый кадр».
- Анимированный HEIC/AVIF (последовательности изображений) не поддерживается; не поддержаны APNG, RAW, многослойные форматы.
- Размытие в стеклянном стиле даёт система Windows: при отключённых «эффектах прозрачности» акрил становится однотонным,
  при перетаскивании окна оно может немного отставать.
