# Универсальный конвертер изображений

Курсовая работа: настольное приложение для пакетной конвертации фотографий (C++20, Qt 6 Widgets, CMake).
Реализован «минимум курсовой» из ТЗ (п. 12.1): окно, drag & drop, определение формата по содержимому,
JPEG/PNG/BMP/WEBP, настройки, очередь с отменой и повтором, обработка ошибок, предпросмотр.
Видео и интеграция с Проводником Windows — последующие этапы, в код не входят.

## Возможности

- Добавление файлов, папок (рекурсивно) и drag & drop; повторы отбрасываются; импорт идёт в фоне.
- Формат определяется **по содержимому** (сигнатуры + проверка декодером); расширение — только подсказка.
  `photo.jpg`, внутри которого PNG, распознаётся как PNG с предупреждением.
- Доступные форматы строит `CodecRegistry` из реально загруженных плагинов Qt: нет encoder — формат не предлагается.
- Предупреждения **до** запуска: потеря прозрачности (заливка выбранным фоном), сжатие с потерями,
  потеря ICC/метаданных, анимация (только первый кадр или отказ), несовпадение расширения.
- Очередь: ожидание → выполнение → успех / ошибка / отмена / пропуск, прогресс по каждому файлу,
  отмена, явный повтор, ограниченная параллельность (по умолчанию 2 потока). Ошибка одного файла не останавливает пакет.
- Безопасная запись: временный файл с непредсказуемым именем в папке назначения → проверка
  (размер, повторное чтение, размеры) → переименование. При ошибке/отмене остаток удаляется. Исходник не изменяется
  и никогда не выбирается как путь результата. Конфликт имён: суффикс `(1)`, замена (с подтверждением) или пропуск.
- Предпросмотр: debounce выбора, отмена устаревшего запроса, scaled read, LRU-кэш с ключом из пути/времени/размера/версии декодера.
- Запуск из командной строки: `UniversalImageConverter.exe [файлы...] --format webp --quality 85 --output D:\out --start`,
  `--list-codecs` — вывести доступные форматы.

## Архитектура

```
app/                  точка входа и корень композиции (выбор реализаций портов)
src/domain/           форматы, модели, состояния, Result — без Qt и Windows API
src/application/      сценарии: импорт, анализ, план, движок, очередь, превью; порты IImageDecoder/IImageEncoder
src/infrastructure/   qt_imageio (QImageReader/Writer), settings (QSettings)
src/ui/               Qt Widgets: MainWindow, FileListModel, DropArea
tests/                unit и integration (Qt Test)
```

Зависимости направлены к абстракциям: `ui → application → domain ← infrastructure`.
`uic_core` (domain + application + infrastructure) не зависит от Qt Widgets; GUI-поток не декодирует и не конвертирует.

| Класс | Роль |
|---|---|
| `FileImporter`, `FileValidator`, `FileAnalyzer`, `FormatDetector` | импорт, проверка пути, анализ, сигнатуры |
| `CodecRegistry` | реестр возможностей чтения/записи |
| `ConversionPlanner` | совместимость и предупреждения до запуска |
| `ConversionEngine` | decode → ImageBuffer → encode → проверка → фиксация |
| `QueueManager` | задачи, состояния, пулы потоков, отмена, повтор |
| `OutputNamer`, `AtomicFileWriter` | имена и атомарная запись |
| `PreviewController`, `ThumbnailGenerator`, `PreviewCache` | предпросмотр |
| `SettingsManager`, `CommandLineHandler` | настройки и аргументы запуска |

## Сборка (Windows, MSYS2 UCRT64)

```bash
pacman -S mingw-w64-ucrt-x86_64-{gcc,cmake,ninja,qt6-base,qt6-imageformats,qt6-tools}
export PATH=/c/msys64/ucrt64/bin:$PATH
cmake -S . -B C:/uic-build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build C:/uic-build
ctest --test-dir C:/uic-build --output-on-failure
```

Важно: **каталог сборки должен быть с ASCII-путём** (например `C:\uic-build`): `moc` Qt не создаёт файлы
в путях с кириллицей, как у папки «Курсовая работа».
Для запуска вне MSYS2 выполните `windeployqt6 UniversalImageConverter.exe`.

WEBP работает через плагин `qt6-imageformats`; HEIC/AVIF в сборку не входят (нужны отдельные кодеки и проверка лицензий).

## Известные ограничения

- Метаданные EXIF/GPS не переносятся (Qt Image I/O их не записывает) — приложение об этом предупреждает; ориентация применяется к пикселям один раз; ICC сохраняется там, где формат поддерживает.
- Отмена срабатывает между этапами конвертации, а не посреди декодирования одного файла.
- Анимация (GIF/WEBP) сводится к первому кадру с предупреждением либо отклоняется настройкой.
